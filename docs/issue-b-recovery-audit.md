## Answers to the eight accounting questions

1. **What counts?** One entry into `_recover`: a rate-limited search/repath/priority trial. It is charged before selection, dispatch and completion; none of those later phases charges another attempt. A completed successful detour is not refunded.
2. **Can no waypoint consume one?** Yes. If all twelve candidates fail, the final destination is installed as fallback and A is already incremented. Source comments explicitly treat repath/priority adjustment as useful bounded work. Later full-graphical1 records exactly this kind of fallback and recovers successfully; it does not demonstrate fallback exhaustion.
3. **Can two paths charge one cycle?** No second production increment exists. With unchanged defaults, `.75` progress sampling, `2.5` minimum interval and `2.0` duration prevent overlapping normal attempts; C's second leg does not charge A. `_recover` itself has no cap/cooldown guard and direct private calls or nondefault interval<=duration could restart an active cycle, but those are not the original stress configuration or a demonstrated historical defect.
4. **Can retries return to an ineffective route?** Yes: both selectors have no previous-candidate memory; identical geometry/positions/scores pick the same candidate or final fallback. H resumes the same final path after any one leg. C protects Issue A by clearance filtering and one extra leg, but can still choose identical bounded paths on later attempts. No original Issue B candidate sequence was recorded.
5. **Can expiry precede meaningful movement?** Yes. R accumulates active simulation time, not displacement. Waiting for avoidance, a physical blockage, slow movement, or path initialization can consume two seconds. This is intentionally bounded. There is no source promise that every selected detour completes; no observed focused episode in the six old traces reaches expiry (all end in approximately0.4-0.75s).
6. **False or erased progress?** Temporary-target changes do not change the metric: `_remaining_path_length` always queries the final destination. Small advances accumulate because B only moves on >=.3 progress; detours away from final create debt. Meaningful final progress can clear a not-yet-reached temporary waypoint—an intentional resume rule, whose adequacy depends on geometry. Pursuit and explicit topology resume carry signed credit/debt across legitimate metric changes; fresh public commands intentionally reset it. Empty/nonfinite path results and uncoordinated external map changes are not fully adjudicated by these tests, but no such original event is recorded. Original stress has fixed target/static map and no pursuit/topology controller.
7. **Stale callback/order interference?** The implementation blocks submitted=-1, wrong-version, stopped, suspended, disabled and second-same-frame moves. It does not tag a velocity result with the exact target/submission that generated it. A recovery target change keeps the same order; after resubmission the version alone cannot independently prove callback freshness. This is a telemetry boundary, not evidence of misordered Godot delivery or eight-attempt exhaustion. V1 traces lack their absolute/relative frame offset; final schema2 adds it. Arbitrary synchronous self-free during state callbacks also lacks uniform explicit self-validity checks; it was not an original stress interaction and is not classified here as a demonstrated Issue B mechanism.
8. **Which bounds versus defects?** A rejected impossible command, eight spent recovery entries followed by eligible renewed congestion, a90-second command deadline, or invalidation by topology are explicit finite outcomes. The cap intentionally survives successful progress and thus limits total work per command, not consecutive failed detours. Original Issue B violates the unchanged reachable-route acceptance test; the available evidence does not establish that its counter was charged twice, reset improperly, expired wrongly, or that any specific code defect caused it. Do not extend/reset the budget merely to avoid that failure.

## Evidence-supported experiment direction (not a demonstrated defect)

The accounting distinguishes **single persistent failure** from **budget accumulated across episodes**. A controlled public-command mover with successive temporary obstructions could consume real attempts, make meaningful progress after each clearance, and later fail on renewed congestion because A never resets. Its control should provide the same final route/obstacles/goal and clear the temporaries before recovery admission, leaving the later obstruction unchanged. Do not preset A, change thresholds, or repeatedly replace the mover's order. Every obstacle must be a normally registered unit using ordinary placement/movement; record when it parks, each actual attempt entry, final-route progress, waypoint/expiry reason, and A continuity. This would verify a generic per-command budget mechanism, **not recreate unrecorded Issue B events**. If such sequential budget expenditure is not supported by the existing trace analysis beyond the observed two-episode case, prefer a single fallback-versus-usable-detour experiment/control first rather than manufacture an eight-obstruction course merely to force failure.

No new accounting defect is demonstrated by source inspection alone. Any hypothesis still needs an event sequence connecting it to Issue B; the original `attempts=8` value is insufficient to select between these paths.
