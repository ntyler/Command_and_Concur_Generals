# Full-game request and source inventory

The requested scope is the complete Generals/Zero Hour experience: original
commands and mouse interaction, economy and match rules, combat and defensive
behaviors, AI, upgrades/prerequisites/general abilities, entry menus, map selection
and skirmish setup. The home screen must also offer manual map building and
AI-prompt map generation. This is an expansion beyond the previous visual import.

**The full game has not been ported or verified.** The current Godot controllers
still implement the prototype's rules. Copying original INI, map and window files
does not make their C++ behaviors execute in Godot. The home screen now connects
the playable prototype and Object Library. Original skirmish setup, the map editor,
AI generator and complete original rules are still outstanding.

## Runtime decision — Godot with original behavior

The owner selected **Godot**, with the existing game's rules and AI preserved
when ported. Godot owns the application and rendering; original simulation and
AI behavior must be translated or integrated into that runtime. Launching the
original executable is not the selected implementation. The prototype's balance,
reinforcement coordinator and navigation are not substitutes for original rules
or AI, and their existing validation does not establish original-game parity.

Preserve original costs, durations, prerequisites, upgrades, general abilities,
input/command semantics, targeting, combat, economy, AI scripts/team composition,
state transitions and scheduling. Each ported routine needs source provenance
and comparison evidence. Keep unsupported behaviors explicit; do not silently
replace them with simplified behavior or mark them implemented because their
INI declarations load. Any deliberate departure from original behavior must be
identified separately. The original 30-Hz logic cadence and float32 rounding
also matter independently of Godot's render rate.

The home screen, map/skirmish setup, manual map builder and AI-prompt generator
remain authorized scope. AI-assisted map authoring is separate from the original
RTS opponent AI. A real generator needs a configured local model or hosted
provider; the provider preference has been requested. A keyword generator must
not be presented as AI. Maps generated by AI must remain manually editable and
pass the same structural and playability checks as manually authored maps.

The local original-engine checkout is `D:/GitHub/CnC_Generals_Zero_Hour`.
Its README lists legacy build dependencies and missing third-party libraries.
The installed games also contain `generals.exe` and `WorldBuilder.exe`; this
inventory has not launched or validated those executables. Original online/login
services have not been tested or recreated, and an offline profile must not be
presented as authenticated online access.

## First Godot parity foundation

The completed first import preserves **67 Zero Hour rule files / 4,330 root
definitions**, including 1,869 Object definitions, 235 ObjectReskins, 820 command
buttons, 472 command sets, 363 weapons, 182 locomotors, 83 upgrades and 96 sciences.
`assets/generals_rules/zero_hour_rules.json` retains ordered nested fields, repeated
module declarations, source paths and source hashes. Values keep original units;
loading the syntax does not implement all field/default/inheritance semantics.
`GeneralsRules` exposes the data in Godot without rewriting prototype prices.
For example, the original Dozer costs 1000 and takes 5 seconds, the Ranger costs
225 and takes 5 seconds, and Barracks cost 600 and take 10 seconds. These differ
from prototype rules and have not yet been applied to its matches.

The original opponent also depends on loose `Data/Scripts/*.scb` files. Five loose
SCB/INI files from both installations are now copied and hash-verified separately
from the BIG archive manifest. All four skirmish/multiplayer programs were decoded
and re-encoded **byte-for-byte identically**. Their Godot-readable JSON retains
script order, conditions, true/false actions, typed parameters, difficulty flags,
groups, player slots and team dictionaries. Zero Hour's skirmish program contains
**3,957 scripts / 1,340 teams / 14 player slots**. ObjectsList, PolygonTriggers and
WaypointsList chunks are explicitly retained as opaque data; legacy parameter
healing and complete script execution are not yet implemented.

`GeneralsAIProgram` loads/indexes the original program and lists missing operation
handlers. Zero Hour skirmish requires **33 condition types and 56 action types**.
Unknown/invalid handlers remain unsupported; a missing file cannot load the
prototype AI in its place. Original INI data declares Boss General playable too;
that declaration is preserved, while actual menu eligibility is a separate
original-code rule to port. No assumption that the original menu exposes all
13 declarations is made.

`GeneralsAITiming` ports the original base/team scheduling control flow, integral
duration conversion and guard-retaliation exit predicate. `GeneralsLogicClock`
supplies a 30-Hz cadence with Pause/Resume/close checks, but is not yet the
authoritative clock of a complete original-rules match. Source-derived routines
retain the [original EA source notices](../licenses/README.md).

The oracle builder extracts **five unmodified original C++ routines**, compiles
them with GCC, and records their outputs and source hashes. Minimal environment
adapters supply player enablement, queue/base callbacks and positions; those
adapters do not stand in for validation of complete production or AI. Comparison
covers 560 scheduler cases / 4,480 observed ticks, 25 duration cases and 224 guard
cases, including ordering, timer boundaries, callback changes and horizontal
range checks that ignore altitude. Guard fields convert to original float32
before multiplication/comparison, including fractional values at range boundaries.

Saved final Godot validation: `validation-output/m8/generals-native-parity-20260910-04`.
Headless and graphical executions each pass **4,760 checks**: **9,520 total**,
zero assertion failures, native errors/warnings, hangs, abnormal exits or shutdown
resource diagnostics. These are data/kernel tests, not visual gameplay acceptance
or human playtesting. All 496 saved source hashes matched at run completion;
only this report changed afterward. The 12 Python importer tests also pass,
including all four actual SCB byte-for-byte round trips and malformed-data checks.
The aggregate audit is `validation-output/full-game-port/godot-parity-summary.json`.

Earlier evidence is retained separately. Phase `generals-native-parity-headless-20260910-01`
had two fixture assumption failures (Boss General's flag and the exact
`CONDITION_TRUE` name), with all native routine comparisons passing. Phase
`generals-native-parity-20260910-02` passed 4,696 checks per display mode before
the fractional boundary cases were added. Phase
`generals-native-parity-boundary-20260910-03` reproduced 12 guard comparison
failures caused by the port's scalar precision. Phase 04 includes those cases
and the correction; earlier passing counts are not added to its final coverage.
Importer/compiler attempts and diagnostics remain under
`validation-output/full-game-port/`, including the original native oracle and
its boundary-expanded successor in `native-reference-02/`.
